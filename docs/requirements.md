# Requirements

Short requirements document for Wnesny (ونسني). It lists what the system must do, who uses it, and which milestone delivers
each part. "Done" means it exists in the repository today and is covered by tests.

## Users (actors)

| Actor | Description |
|-------|-------------|
| Member | A registered user. One account can be a **driver** (offers rides) and a **passenger** (asks to join rides); there are no separate account types. |
| Driver | A member acting on a ride they published. |
| Passenger | A member acting on a request to join someone else's ride. |
| System (simulator) | Generates and loads the synthetic data used for analysis. |

## Functional requirements

| ID | Requirement | Milestone | Status |
|----|-------------|-----------|--------|
| FR-01 | A person can register with name, e-mail (unique) and password (stored only as a hash). | M2 (data layer) | Done |
| FR-02 | A member can keep an optional profile (bio, education, visibility setting) and choose interests from a fixed catalogue. | M2 | Done |
| FR-03 | A driver can publish a ride with origin, destination and a future departure time. | M2 | Done |
| FR-04 | A passenger can request to join a scheduled ride, but not their own ride and not twice. | M2 | Done |
| FR-05 | Only the driver can accept or reject a request. A ride has at most one accepted passenger. | M2 | Done |
| FR-06 | A chat between driver and accepted passenger is created on acceptance; only those two can write. | M2 | Done |
| FR-07 | The driver can start and complete a ride, or cancel it while it is still scheduled. An accepted passenger can cancel while the ride is scheduled. | M2 | Done |
| FR-08 | After completion, driver and passenger can review each other once (rating 1 to 5). | M2 | Done |
| FR-09 | Members get notifications about requests, acceptance, cancellation and completion. | M2 | Done |
| FR-10 | The project data is generated by a seeded simulator, checked by a validator and loaded into the database. | M2 | Done |
| FR-11 | Web pages: Home, Profile, Find a Ride, Dashboard (charts of ratings and distributions). | M4 | Planned |
| FR-12 | Statistical analysis: confidence intervals, hypothesis tests, distribution fits, regression/correlation. | M3 | Planned |

The AI matching component from the M1 proposal is not part of the current scope of this repository (see
[proposal/README.md](proposal/README.md)).

## Non-functional requirements

| ID | Requirement |
|----|-------------|
| NFR-01 | Data integrity is enforced by the database (foreign keys, CHECK constraints, unique indexes), not only by Python code. |
| NFR-02 | Privacy: all data is synthetic; coarse areas only, no live GPS; no real personal data. |
| NFR-03 | Reproducibility: the same seed produces the same data; the project runs from a clean machine by following the README (or with Docker). |
| NFR-04 | Quality: Python 3.10 or later, modules not notebooks, at least 10 automated tests (109 today), and a Git workflow with pull requests. |
| NFR-05 | Security: passwords are hashed, no secrets in Git, the production configuration refuses to start without `SECRET_KEY` and `DATABASE_URL`. |
